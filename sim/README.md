## 场地改 LUTRAM 行字副本（B2 步实测）

做法：`state`(480 位 FF) 仍是主存储与对外接口，另挂 **8 份 24×20 行字副本** `state_ram[0:7][0:19]`
（分布式 RAM，单读口一拍一行，分工固定：0/1=P1 渲染下行/本行、2/3=P2、4/5=幽灵、6/7=旋转），
所有场地判定改读副本；三条写路径（清场/落锁/消行搬移）统一走一个『行写口』，一拍拍一行，
镜像与 8 份副本**同拍写同一行**。消行搬移由『1 拍整体搬』改成『20 拍逐行搬（行号降序）』，
`frame.v` 的 `state_color` 跟着 Playfield 导出的 `mv_we/mv_row` 同步搬（原来 frame 里另有一份 1 拍搬移，
必须一起改，否则颜色与场地会错位）。

## 幽灵"悬空"第二处根因与修法（第二批）

`ghost_scan_r` 的逐行扫描上限是 20（场地 20 行 + 形状 ROM 的行偏移 ≤0，锚点最多到第 20 行）。
原来扫到 20 仍没被挡时走 `else ghost_done <= 1'b1;`，**只置完成、不写落点** →
落点保持在上一轮扫描的旧值。只要方块换到"行偏移里没有 0"的形状（典型是 Z 的 rot2：
`(-1,-2)(-1,-1)(0,-1)(1,-1)`，锚点要落到 20 行），幽灵就会停在旧位置（比正确位置高 1 行）→
看起来就是"幽灵悬空"，同时硬降也会少落一行。

修法：扫到上限就按"落点=20"落值（并把 `ghost_blk_oth` 清 0），P1/P2 对称：

```
else begin
    ghost_done <= 1'b1;
    ghost_blk_oth <= 1'b0;
    counter_ghost_r_t <= ghost_scan_r;   // 到行上限: 落点就是这一格
end
```

另外把 Hold（换块）也加进重扫触发（`hold_up`/`hold_up2`），覆盖"方块还在第 0 行时换块、位置没变
所以 `new_piece` 不触发"这一种漏扫。

回归断言（`sim/duo` 第 20 组）：先给 4 格同行的形状（落点应为 19），再换成行偏移 -1/-2 的形状，
落点必须变成 20（旧代码会停在 19）、幽灵要画在第 19 行、硬降要真的停在落点。改前版本这 4 条必失败。


## 「幽灵/落底看错场地」的根因（硬件侧，综合层面）与修法

现象：三套仿真全过，但上板后像"判定/幽灵看不到已落方块"（幽灵压在别的方块上、方块落进堆里）。
查法：打开 `synth_1` 的 checkpoint，把 RAM 原语的管脚连接打出来看（`get_pins`/`get_nets`）。

- **旧写法**（`reg [23:0]state_ram[0:7][0:19]` 一个 3D 数组 + 组合写口 `row_a/row_d/row_we`）：
  Vivado 认出"3D RAM"后按"8 份内容相同"做合并，读地址占满了 `ADDRA/ADDRB/ADDRC`，
  而 **`ADDRD`（分布式 RAM 的公共写地址）被接到了某个副本的读地址上** →
  写入落到错误的行 → 副本内容与镜像 `state` 不一致 → 判定/幽灵读到的是坏场地。
  （依据：RAM32M 的 unisim 模型里写地址用 `ADDRD`、读用 `ADDRA/B/C/D`；
  旧网表里 `ADDRD` = `state_ram_reg[2]...` 的读地址，`WE` 还是派生出来的。）
- **新写法**（8 个独立二维数组 `sram0..sram7` + 写口打一拍 `wr_we/wr_a/wr_d` + 读地址一律取 5 位）：
  综合后每份都是独立的 `32 x 24` RAM，**`ADDRD = wr_a`、`WE = wr_we`、`ADDRA/B/C` = 该副本自己的读地址**，
  写地址正确。

结论：**分布式 RAM 的写地址必须是显式信号、且与读地址分开；不要把多份同内容副本塞进同一个 3D 数组**
（会被合并成带多读口的 RAM，写地址就没位置了）。现在 8 份各自独立，仿真 + 网表双重核对。

另外：幽灵重扫触发里接上了"真正写入"的 `wr_we`（打拍后的写选通），保证重扫一定读到写后的场地；
`mv_we/mv_row` 也一起打拍，frame 的 `state_color` 与场地搬移严格同拍。

这一版的面积（`Flow_AreaOptimized_high`）：**LUT 11921 (57.31%)**、LUT as Logic 11788、
LUT as Memory 133（128 分布式 RAM + 5 SRL）、FF 4739、F7 1668、F8 269、BRAM 14、DSP 3、IOB 34；
模块 `Playfield` 6827。

## 时序收敛：两条既有违例路径的修法（A 项）

上板能用那版的 P&R 实测：**WNS = −1.16ns，8 条违例**，全部来自两条**原本就有**的路径：

1. `scoring`：分数→BCD 是"20 次双 dabble 全挤在一拍"（14 级组合链）→ 计分 ROM 地址路径超时；
2. `Playfield`：`C_num/R_num` 用 24/20 级**优先级搜索**算出来 → 渲染取色
   （`hcounter_r → cell_r/sc_r`）超时。

修法（都做到等价，并各自带回归断言）：

- **② `C_num/R_num` 改成算术式**：场地是 32px 均匀格子 ⇒ `C_num = (hcounter−321)>>5`，
  并保留"每格 30px、末尾 2px 给哨兵 24"的原行为。
  `sim/duo` 第 22 组把**原来的逐格比较**在 tb 里重写当参照，2283 个采样点逐点比对一致。
- **① `scoring` 的 BCD 改成串行双 dabble**：一拍只做一次"每位比较+加 3，再左移一位"，20 拍
  出一轮结果（≈0.3µs，显示看不出来）。`sim/level` 第 7 组用 `score/10^k % 10` 当独立参照，
  7 个值逐位一致。
- 另：`impl_1` 的实现指令改成**时序驱动**（place = ExtraTimingOpt，phys_opt/route =
  AggressiveExplore），已写进工程文件。

结果：**WNS = +0.311ns、WHS = +0.111ns、违例 0 条**（`All user specified timing constraints are met`）；
资源：LUT 16206 (77.9%)、FF 4591、BRAM 12、DSP 5、IOB 34。
