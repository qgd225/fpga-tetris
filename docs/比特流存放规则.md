# 比特流存放规则

- 唯一开发目录：`D:/vivado_project/Tetris`，仅使用 `main`，历史版本保存为 Git 提交。
- 唯一发布/下载文件：`D:/vivado_project/Tetris/bit/Tetris.bit`，仅保留当前最新版；不再通过其他目录或目录联接发布。
- Git 只跟踪 `bit/Tetris.bit`，不提交根目录或构建缓存里的其他 `.bit`。提交时记录实际源码来源和验证情况。
- Vivado 的 `impl_1` 保留 `write_bitstream` 后置发布钩子；脚本构建与界面生成成功后更新同一个文件，失败不能发布。
- 发布脚本将文件写入所构建工程自己的 `bit` 目录；其他电脑克隆后也无需兄弟目录或目录联接。
- `.runs`、`.cache` 等是生成缓存，不作为另一份开发版本，不纳入 Git。候选验证若需独立输出，只用临时构建目录，验收后清理。
- 被删除旧目录的源码、配置和未提交内容已纳入主线历史；恢复入口见 `workspace-unification.md`。旧手工 bit 副本和缓存已不再保留为本机版本。

## 当前对外发布

本地和 GitHub 仅维护 `main`。用户已确认 HDMI 游戏音效版上板成功，并要求降低音量后发布。当前版将振幅从 ±4096 降至 ±1024，发布文件统一为 `bit/Tetris.bit`；构建验证和校验值见 `HDMI音效测试.md`。后续改动直接在唯一目录的 `main` 完成，通过提交记录保留历史，不再新建分支或并行工作区。
