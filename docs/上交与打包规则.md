# 上交与打包规则

更新：2026-10-27。本文是 Git 提交／GitHub 上传范围和作品提交压缩包的核心规则。`Tetris.sim/` 为作品必附内容；本文只规定交付方式，不表示已经完成打包、上传或赛事验收。

当前工程、发布与待人工验收状态见 [README.md](README.md)，工程操作与验证标准见 [AGENTS.md](AGENTS.md)，完整导航见 [资料索引.md](资料索引.md)。本文不重复维护玩法、世界观和时序阈值。比赛正式通知对材料、命名、格式、大小、时长和提交入口有明确规定时，按该通知执行并更新本文件，不把历史计划中的估计当作正式要求。

## 1. 交付对象与版本一致性

GitHub 用于保留完整、可维护的工程及历史；作品压缩包用于评审打开工程、下载已验证 bit、运行演示和阅读提交材料。两者使用同一确定版本的正式文件，按下表选择内容。

打包前冻结本次交付清单，核对源码、约束、IP 配置、初始化数据、资产、测试台、文档、验证证据和正式 bit 的对应关系。只认 `bit/Tetris.bit` 与配套 `bit/Tetris.bin` 为本次正式发布固件，二者配置数据必须一致；标准运行目录中的新生成 bit 必须另行验证，不能仅凭时间较新替换提交版本。

用户未要求提交或上传时只准备清单与文件；Git 提交、GitHub 推送和赛事上传分别按用户授权执行。既有未提交改动要区分来源和验证状态，不能用 `git add .` 混入本次范围。文件迁移同时记录旧路径删除与新路径新增，删除旧源码目录不能漏掉新位置和许可证。

## 2. 文件范围

| 文件／目录 | Git 与 GitHub | 作品压缩包 |
| --- | --- | --- |
| `Tetris.xpr` | 纳入当前工程配置 | 必须，保留工程相对路径 |
| `Tetris.srcs/` | 纳入实际源码、约束、IP 配置与初始化输入 | 必须，包含引用的 `.v/.sv/.vh/.xdc/.xci/.coe/.mem` 等完整输入 |
| `Tetris.sim/` | 纳入全部正式测试台 | **必须附带**，保留分组和 `*tb.v`、`*tb.sv`；不夹带运行产物 |
| `assets/` | 纳入原始资产和生成配置 | 纳入本作品使用的原始资产与配置，便于维护和核对生成结果 |
| `tools/` | 纳入必要的资产生成、构建、验证、发布工具与说明 | 附相关工具源码；只有通过干净目录复验的入口才可宣称可直接运行 |
| `pc/` | 纳入 PC 显示、控制、ARP 工具源码和使用说明 | 本作品包含 PC 画面／键盘演示，须附 PC 源码、`pc/网口自测.bat`、`network_selftest.py` 及同目录支持模块与使用说明 |
| `TetrisPC.exe` | 保留正式 PC 便携成品，有变更时提交 | 附带经干净目录自测的便携 PC 程序，自带运行依赖；同时核对 EXE 与本次 PC 源码指纹 |
| `bit/Tetris.bit`、`bit/Tetris.bin` | 当前版本树只保留最新一对固件，均为binary | 必须，只附同一验证版本的最新版bit与配套bin，分别记录SHA256 |
| `docs/` 核心资料 | 纳入六份核心正文 | 必须附当前核心正文；提交专用导航须与实际包内内容一致 |
| `docs/技术说明/` | 纳入必要编码、来源与许可说明 | 附相关技术说明及原作者声明、完整许可证、上游版本记录 |
| `docs/reports/` | 纳入有保留价值的正式验证结论、输入指纹及预览 | 精选与当前交付对应的回归、资源、时序、DRC 和演示预览证据 |
| `docs/计划书/`、历史／学习／过程资料 | 有维护价值的内容可保留，候选明确标记身份 | 默认不附无关旧方案、学习资料和清理过程；正文所需的补充材料单独选择 |
| 根目录 `README.md`、`AGENTS.md` | 保留导航入口 | 保留入口；另提供清晰的提交说明，不把仓库维护导航直接当作评审指南 |
| `.gitattributes`、`.gitignore` | 纳入编码与忽略规则 | 保留便于核对编码与维护，但 Vivado 生成不依赖 Git 元数据 |
| 设计报告、视频、截图等赛事材料 | 已定稿且适合仓库保存时按需纳入 | 按比赛正式要求附带；没有要求的格式、数量和时长不自行冒认 |

第三方 HDL 已直接纳入 `Tetris.srcs/`，不额外建立 `third_party/` 源码目录；其作者声明和许可资料必须随作品保留。后续新增第三方模块同样处理。

## 3. Tetris.sim 与仿真复现

`Tetris.sim/` 是明确必附项，不能因为 Vivado 综合不读取测试台而将其从作品中剔除。该目录仍只放正式 `*tb.v`、`*tb.sv` 测试台，保持原分组，不放脚本、向量、缓存、波形或日志。数量随版本变化，按本次清单逐项核对，不沿用旧报告中的固定数量。

测试台源码与可运行的完整仿真环境分别说明。当前本机功能回归入口为 `tools/run_functional_regression.py`，其分组运行支持位于 `temporary/sim/`，运行脚本、参考数据和编译辅助文件保存在本机 `temporary/sim/`；该目录按工程规则不整体提交 Git，也不整体塞入作品压缩包。

若比赛要求或包内说明承诺“可复现完整仿真”，打包时须额外筛选并提供运行所需脚本、静态参考数据、必要辅助模块及依赖说明，放在提交包独立的仿真支持目录，例如 `仿真支持/`，保留清晰的入口与分组对应关系。运行输出定向到提交包自己的临时目录，不写入 `Tetris.sim/`。

筛选支持文件时排除 `build/`、`build_music/`、`logs/`、`__pycache__/`、`.Xil/`、`xsim.dir/` 等生成物。修正依赖原电脑的绝对路径后，在异地解压目录实际跑通承诺的测试，再记录工具版本、入口、覆盖范围和结果；仅附测试台时如实说明“提供测试源码，未提供完整一键仿真环境”。

## 4. Vivado 生成与辅助工具边界

提交包默认以 Vivado 界面打开 `Tetris.xpr`、执行标准综合／实现／Generate Bitstream 为工程重建入口。当前正式工程没有生成前后脚本钩子；工程登记的 HDL、约束、IP 配置和初始化数据必须都能在包内找到。

Vivado原始输出为 `Tetris.runs/impl_1/Tetris.bit`，不会自动覆盖正式bit/bin。通过验证后的发布入口同步生成／保存 `bit/Tetris.bit`、`bit/Tetris.bin`；仅补bin可运行 `tools/生成bin.bat`，无需重新综合。维护规则、计划书、PC 程序和脚本构建入口不作为 Vivado 界面生成的依赖。

`tools/生成bit.bat` 是另一套完整构建／验证／保存入口，当前还依赖本机仿真支持、Python、Git 和工作区状态。附带工具源码不等于承诺其能在无 `.git/` 的解压目录直接运行。若要将它作为提交包可运行入口，须先补齐支持文件，处理 Git 依赖和路径，并实际复验；不能为此把整个 `.git/` 或本机缓存装入压缩包。未适配时，提交说明明确使用 Vivado 界面重建。

## 5. 必须排除的内容

- `.git/`、密钥、账号信息、凭据及个人运行数据。
- Vivado 缓存、运行与生成目录，例如 `Tetris.runs/`、`Tetris.cache/`、`Tetris.hw/`、`Tetris.ip_user_files/`、`Tetris.gen/`；IP 自动生成的 HDL／仿真／综合缓存不代替 `.xci` 与初始化输入。
- `temporary/` 整个目录，以及其中的候选构建、临时预览、日志和中间网表；确需交付的仿真支持按上一节单独筛选。
- `.jou`、过程 `.log`、`.wdb`、波形、编译可执行快照、临时 DCP／网表及 Python 缓存。正式验证需要的资源／时序报告、结论和机器可读汇总可保留。
- 历史 `Tetris_*.bit`／`Tetris_*.bin`、过期候选和多余副本；Git当前树和作品包只附 `bit/Tetris.bit`、`bit/Tetris.bin`。
- 个人成绩、启动错误、静态 ARP 等运行日志，以及此前生成的作品 ZIP 本身，避免套娃打包。
- 与当前交付无关的旧计划、学习资料和失效截图。未采用的候选 UI 不得冒充当前实现或替换已确认视觉基准。

排除缓存前先核对工程输入，不能把 `.mem/.coe/.xci` 等正式初始化与 IP 配置误删。正常 GUI 生成所需的 `Tetris.xpr` 与 `Tetris.srcs/` 必须完整。

## 6. 提交说明与目录

压缩包保留一个清晰的项目根目录，使 `Tetris.xpr`、`Tetris.srcs/`、`Tetris.sim/`、`bit/`、`pc/`、`tools/`、`assets/` 和精选 `docs/` 的关系保持明确，不把全部文件压平成一层。默认命名可用 `Tetris_作品提交_YYYYMMDD_版本标识.zip`，赛方要求命名时按其要求。

在提交包中生成单独的 `提交说明.md`，说明以下内容：

1. 作品名称、版本、制作日期，以及适用板卡、器件和 Vivado 版本。
2. 从解压到打开工程、生成 bit、下载成品的明确步骤；附接线、显示／音频与按键说明。
3. PC 程序的启动、网线和网卡配置、IP／ARP 与必要依赖。
4. `Tetris.sim/` 的位置、测试覆盖；是否附带可运行支持环境及其入口。
5. 设计报告、演示视频、截图、验证报告及来源许可的实际位置。
6. bit与bin的路径、各自SHA256、转换一致性和对应源码／验证证据，自动验证与待人工上板、PC 实际收流、试听的真实状态。

作品说明和导航只能指向实际打包的文件。精选资料导致导航变化时，在打包副本中生成提交专用索引或调整导航，不改写正式工程核心正文与历史验证快照。历史报告中的当时路径可保留并说明其历史身份，但当前生成、启动与关键材料入口不能依赖包外路径。

保持文件原有编码：本地手写 RTL 为 GBK 无 BOM，已声明的上游模块保留 UTF-8，不为打包统一转码。解压所得源文件字节须与选定交付版本一致；若从 Git 导出，核对导出编码后再制作提交包。

## 7. 打包与上交前核对

1. 确认正式版本和所需比赛材料，形成逐文件清单；对未提交源码写明工作区输入指纹，不能仅写一个不包含当前改动的旧提交号。
2. 从正式目录按清单收集文件；必含 `Tetris.sim/`，完整保留工程输入、最新版 bit/bin 和来源许可。
3. 记录包内文件数、路径与大小，对关键文件和 bit/bin 分别计算 SHA256；核对源码／资产／测试台与验收版本。生成清单若列出自身，明确不对自身做递归摘要。
4. 扫描缓存、历史 bit/bin、个人数据和压缩包嵌套，确认关键链接、工程引用和运行依赖都在包内。
5. 在正式工程以外的干净临时目录解压；该目录只用于交付验收，不作为第二份长期开发工程。验证 Vivado 能找到源文件、约束、IP 和初始化输入，无旧目录依赖和脚本钩子。
6. 按包内承诺测试 PC 启动、软件 UDP 回环自测、工具入口与仿真支持；需要外部网口验收时使用双机发送／监听，不以回环代替；若承诺从零生成 bit，完成一次干净目录生成，不能用正式工作区缓存代替该验证。需要实板或人工操作的项目如实列明状态。
7. 仅用于打包且文件字节、路径关系和实际构建输入未变时，可引用已有对应硬件验证；打包时改动源文件、约束、资产或生成配置则重新完成受影响验证和最终验收，不把旧 bit 当成本次生成结果。
8. 封包后记录最终 ZIP 名称、大小、SHA256 和材料清单；按比赛要求完成上传，并核对上传成功状态或回执。未实际执行时只记录“规则已制定”或“待打包／待上传”。

Git 提交和推送的分开授权、分支、提交说明与发布标准仍遵循 AGENTS.md；本文件定义交付内容与打包方法，二者不另维护第二份相互冲突的交付清单。
