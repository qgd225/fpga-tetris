# 第一部分 参考图解读

## 1.1 它做对了什么

参考图没有一根"边框"，但分组极其清楚。四个手段，全不依赖描边：

| 手段 | 做法 | 效果 |
| --- | --- | --- |
| **明度差代替边框** | 面板填 `#0C161E`，比周围更暗 | 读作"凹槽"，比画框安静 |
| **一条 1px 线完成分组** | 标题与面板之间一条浅线 | 一个元素承担"标题区/内容区"分界 |
| **层级靠明度，不靠颜色** | 标题浅灰、内容极暗、点阵几乎不可见 | 近单色反而更"高级" |
| **点阵暗示空槽** | 4×4 个 2px 点，间距 24 | 空的时候不空洞，满了自动被盖住，零额外状态 |

## 1.2 由此确立的语法

**放弃"边框分级"，改用「细线 + 明度 + 点阵 + 分层槽」。**

四种视觉工具：

1. **1px 细线** —— 分隔，不包围；
2. **明度块** —— 分区，靠 6～10% 亮度差；
3. **2px 点阵** —— 暗示可填位置；
4. **3×1px 分层槽** —— 需要"机加工感"的结构。

边界：**分层槽只给场地**。卡座、面板一律用 1px 线 + 明度，否则又回到"到处都是框"。

# 第三部分 组件规格 A：NEXT / HOLD 卡座

## 3.1 关键前提：内容坐标一动不动

M1 的预览内容已验收：NEXT 内容 `x=[176,272) y=[200,296)`，HOLD `x=[176,272) y=[376,472)`，均为 96×96。

# 第四部分 组件规格 B：场地

v3 重点。现状"只是一根线围一圈"，单调的根源是**四边完全对称**——机器不会有四条一样的边。

## 4.1 底面与网格

| 项 | 做法 |
| --- | --- |
| 底面 | `#131D26`（比船壳暗一级，读作凹槽） |
| 网格 | **点阵**：24×20 个点，2×2，`#1C2836` |
| 内阴影 | 上/左 1px `#0A1118`，下/右 1px `#22303D` |

点阵替代连续网格的理由：22px 面被线切碎显得噪；点只在格心留一个记号，空场地读作"待填的插槽"，与"碎片嵌入晶格"同向，且与卡座同一母题。点太密时改为 48px 间距（120 点）。

## 4.2 场地框：四边不同构

**框体**用三层 1px 构成 3px 凹槽（不是 3px 粗线）：

| 层 | 颜色 | 位置 |
| --- | --- | --- |
| 外线 | `#2A3644` | `x=352 / 927`，`y=144 / 623` |
| 中槽 | `#16212B` | 内退 1px |
| 内影 | `#0A1118` | 内退 2px |

四角在槽内各补一个 2×2 `#3A4A58` 螺栓点。

**四条边各承担一种功能：**

| 边 | 功能 | 坐标与做法 |
| --- | --- | --- |
| **顶** | 夹持轨 | `y=[140,144)` 4px 条 `#1A2530`；3 个 8×4 夹爪缺口 `#0A1118`，位于 `x=[428,436)`、`[636,644)`、`[844,852)` |
| **左** | 计量刻度 | `x=[348,352)`；从 `y=144` 起每 48px 一个 4×1 刻度 `#22303D`，共 10 个；每第 4 个加长为 8px `#3A4A58` |
| **右** | 供能端口 | 4 个 6×24 端口 + 汇流管，见 4.5 |
| **底** | 斜向排线 | `y=[624,632)` 8px 带；45° 斜线，判据 `((x+y)&63)<2`，色 `#22303D`，约 9 条（见 4.7.2） |

**为什么四边要不同：**一条等宽框只表达"这里有个边界"；四条各司其职的边表达"这里是一台受夹持、可计量、有供能、会散热的设备"。同样的像素量，信息量差一个量级。

## 4.3 场地底部铭牌

| 元素 | 坐标 | 内容 |
| --- | --- | --- |
| 上沿线 | `y=633`，`x=[352,928)`，1px `#2A3644` | 与底框留 3px |
| 左铭文 | `x=[352,472)`，T3 `#5B6E7E`，字距 +4 | `CONTAINMENT 07`（14 字 ×8 = 112） |
| 右铭文 | `x=[888,928)`，T3 `#5B6E7E`，右对齐 | `24X20` |

**注意：**字库只覆盖 A–Z、0–9 与少量标点，**没有乘号 `×`**，必须写 `24X20`。

**分工：**铭牌只承担"这台机器的身份"，**不承担状态**。状态全部留在顶部仪表带——避免同一信息出现在两处。

铭牌下面的 `y=[648,680)` 仍留给辅助时间（`TIME`），两者只隔 2px，所以铭牌必须 1× 且不加深色底，否则会和 `TIME` 抢视线。

### 4.3.1 左列维修标签块（借自 story 之前那一版）

| 行 | 坐标 | 内容 | 颜色 |

## 4.4 危险带：改分段灯带

替代顶端整条连续红线（借自早期方案）：

- `y=[146,150)`，紧贴场地上框内侧；每 24px 亮 16px、灭 8px，共 24 段；
- `danger_lvl=1`：`#E8A23C`；`danger_lvl=2`：`#D8442E` 并以 2Hz 闪烁；
- 判定仍来自现有 `danger_active`，不新造阈值；
- `danger_lvl=0` 时整条不画——用可见性而非换色表达"没有危险"。

**为什么比连续线好：**连续线只有一个信息（有/无）；分段带天然有节拍，读作"仪表盘上一排灯"，且 24px 步进与格距零成本对齐。

**与计划书 §7.1 的关系：**该节目前是"一条供能轨由场地右侧通向核心下端"。本节把它细化为"四入口 + 一条汇流管"，**机械开合仍只有 §6 核心顶部一处**，不产生第二个开合动画。若不愿改动 §7.1，退化为：只保留 4 个端口（亮/灭），仍用原单轨输送——观感收益约减半，但零冲突。

## 4.6 实现要点

| 绘制项 | 判断 | 估算 |
| --- | --- | --- |
| 3 层框 | 3 组边界比较 | ≈12 LUT |
| 顶夹爪 | 3 个矩形 | ≈12 LUT |
| 左刻度 | `(y-144)` 低位判断 | ≈10 LUT |
| 底排线 | `((x+y)&63)<2` | ≈6 LUT |
| 铭牌 | 共享字库固定文本槽 ×2 | ≈0 |
| 端口 + 汇流 | 4 矩形 + 2 线 | ≈24 LUT |
| 脉冲 | 1 个位置计数器 | ≈8 LUT |
| 危险带 | `x[4:0]` 判断 24 段 | ≈12 LUT |

合计约 **+80～100 LUT**，扣原单一框线约 −8。属设计估算，按门禁实测。

## 4.7 机械感零件库（借自 story 之前那一版）

判断：那一版的机械感**不来自颜色**（它的青框其实更吵），而来自**小而规律的功能标记的密度**——刻度、铆点、排线、下划线、通道。

所以只采纳它的**密度**，拒绝它的**饱和度**。

> **已按用户意见去掉：七段数码管读数。** `TIME` 与 `SCORE` 继续用现有共享位图字库，不新增字形与判据。理由记录在此以免反复：数码管能强化仪表感，但会引入第二套数字字形，与共享字库的统一性冲突；位图字已够读，收益主要在观感而非可读性。

### 4.7.1 边框密度：3px 槽改 6px 通道

旧版场地的框是**双线夹一条 8px 空隙**，那条空隙才是"机加工通道"的观感来源；v3 起初只做 3px，太薄。

| 层 | 厚度 | 颜色 |
| --- | --- | --- |
| 外线 | 1px | `#2A3644` |
| 通道 | 4px | `#16212B` |
| 内线 | 1px | `#0A1118` |

通道内**加刻度**：每 48px 一个 2×4 短刻（横穿通道），`#22303D`，与左边缘刻度同相位。

这才是"密度"的来源——**不是把线加粗，而是在线之间放东西**。

**成本：**通道加厚只是坐标常量变化；刻度判据与左刻度共用 `(y-144)`，约 **+6 LUT**。

### 4.7.2 底部斜向排线

旧版底部有一条 45° 排线带，是整屏最"机械"的一处，而实现极便宜：

- `y=[624,632)`，8px 高；
- 判据 `((x+y) & 63) < 2`，即 45°、2px 宽、间距 64px，约 9 条；
- 色 `#22303D`，只在场地横向范围内；
- 一个加法一个与，比"24 个槽的栅格"更省。

栅格像散热孔，排线像机加工纹——后者更贴这台设备的身份。

### 4.7.3 金属铆点

旧版左轨上有几个小方块，读作紧固件。采纳 4 个，位置固定、**不承担状态**：

| 位置 | 坐标 | 尺寸 | 颜色 |
| --- | --- | --- | --- |
| 场地上部 | `x=[345,349) y=[168,172)` | 4×4 | `#8A5A18` |
| 场地中部 | `y=[380,384)` | 4×4 | `#8A5A18` |
| 场地下部 | `y=[592,596)` | 4×4 | `#8A5A18` |
| 铭牌右端 | `x=[924,928) y=[638,642)` | 4×4 | `#8A5A18` |

用暗琥珀而非亮金属色，避免与"能量"语义抢颜色。

### 4.7.4 玩家标签 P1 / P2

v3 去掉了 NEXT/HOLD 的霓虹描边，双人身份少了一个载体。旧版在画面两端各放一个 `P1` / `P2`，正好补位：

| 标签 | 坐标 | 颜色 |
| --- | --- | --- |
| `P1` | `x=[160,184) y=[116,128)` | `#2FA8B8` |
| `P2` | `x=[1096,1120) y=[116,128)` | `#C4527A` |

1× 字、字距 +2，位于卡座标题上方 24px，与标题同列。**它同时交代"左是 P1、右是 P2"**——这是当前画面缺的一条信息。

### 4.7.5 明确不借的四项

| 旧版做法 | 不借的原因 |
| --- | --- |
| 整圈亮青 / 亮粉描边 | 饱和度抢过方块；v3 用明度语法已解决分组，不必靠颜色划界 |
| `LV0` 与 `00:00` 占满顶部 1/4 屏 | 读数应小、标签更小；大字号只留给结算标题 |
| 左右各一份 HOLD | 计划书 §5.1 已定为单份共享 HOLD |
| 孤立小方块（左上两个无标签盒、左轨零散黄点） | 无功能的装饰会读成"没做完"；每个标记必须是刻度、紧固件或状态之一 |

**另有一条硬性缺陷要防：**旧版把 `CONTAINMENT` 截成了 `CONTAININMEN`。固定文本槽必须做长度断言（见 4.3.1 末段），不能靠人眼发现。

# 第九部分 细化清单（27 条）

1. 全屏 **0 根 2px 及以上单色边框**；
2. 所有分隔线 1px，且**不闭合**；

# 第十一部分 验收

1. **灰度测试**：转灰度后由未参与者排序"标题 > 数值 > 标签 > 线 > 点阵"，一致率 ≥80%；
2. **卡座一致性**：NEXT 与 HOLD 的标题基线、线位置、面板边、点阵起点 1px 内对齐；
3. **内容不位移**：方块仍居原 96×96 区域中心（±1px）；
4. **边框计数**：无 2px 及以上单色边框；场地框为三层 1px 槽；
5. **四边不同构**：顶 3 个夹爪、左 ≥8 个刻度、右 4 个端口、底 ≥7 条 45° 排线；
6. **端口对位**：4 个端口中心与 4 对核心段中心重合（±2px）；
7. **颜色计数**：实际使用 ≤ 42（预算 56）；
8. **红色计数**：仅危险带 2 级、警戒齿、结算标题，其余 0；
9. **铭牌可读**：1 米外可读 `CONTAINMENT 07`，`24X20` 不溢出右缘；
10. **共享可读**：3 人盲测能说出"HOLD 是两人共用"，≥3/3；
11. **核心可数**：1 米外能数出 8 段，≥2/2；
12. **结算亮度**：核心段、刻度、铭牌保持全亮度，只有方块区压暗；
13. **文本不截断**：所有固定文本槽的 `字符数 × (8+字距) ≤ 槽宽`，逐槽断言（防 `CONTAININMEN` 类事故）；
14. **通道有内容**：场地框通道内可见刻度，不是一条空槽；
15. **`P1`/`P2`**：画面左右两端各有一个玩家标签，3 人盲测能指认左右归属，≥3/3。
