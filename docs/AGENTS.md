# Tetris 工程唯一规则

更新：2026-10-26。日常从 docs 根目录核心资料读取当前信息，工程维护规则以本文件为准，交付范围与打包方法另见同目录《上交与打包规则.md》；不再为确认现行规则或设定重复翻阅旧计划、报告。按具体任务需要读取代码、测试、当前参考图或故事设定。用户最新明确指令优先，历史文档不是额外门禁。

## 工作区与语言

- 唯一正式工程：`D:/vivado_project/Tetris`，本地和 GitHub 只维护 `main`，不复制工程、不创建并行 worktree。
- 面向用户的说明和 Git 提交信息使用简体中文；代码、命令、路径、变量及日志原文保留。
- 修改任何代码、脚本、资产生成配置前，先确认本次是否提交 Git、是否推送 GitHub，并分别记录。用户已明确的本次选择不重复询问。每轮按受影响范围验证，不再另问是否开启每轮复验。
- 修改代码前关闭正在运行的 Vivado。用户已授权退出 Vivado；先保存可保存的工程状态并正常退出，再确认没有构建或 Vivado 进程使用相关目录。若仍有未保存状态或无法正常退出，先说明，不强制结束造成数据丢失。
- 新要求出现时，询问是否作为长期规则加入本文件；未确认前只按当前任务执行，不自动升级为永久规则。用户明确要求“加入规则”时直接写入，不重复确认。

## 源码与第三方模块

- 第三方 HDL 直接纳入 `Tetris.srcs/sources_1/new/` 等对应正式源码目录，与本地模块一起登记、编译和维护；今后也按此方式接入，不建立独立的 `third_party/` 源码依赖目录。保留模块边界，不为目录整合随意改写模块逻辑。
- 原作者声明、许可证和固定上游提交须保留，来源资料集中在 `docs/技术说明/第三方来源/`。保留上游注释编码，并在 `.gitattributes` 对对应文件声明；同步更新工程引用、仿真编译路径和构建输入指纹，不留失效路径。

## 资源与时序

- 不设 LUT、寄存器、BRAM、DSP 或各模块净增量的人为预算；不再遵循 `docs/story-execution-gates.md` 及旧计划中的资源门禁。按画面、音频和功能需要使用资源，但必须适配目标器件并完成合法布局布线，不能为了用满资源而增加功能。
- 时序唯一验收标准：完整布线后 WNS ≥ 0.000 ns、WHS ≥ 0.000 ns，TNS = 0、THS = 0；不额外要求 +0.050 ns 的正余量。
- 不得以降低目标时钟、错误 false path/multicycle 或掩盖真实路径的方式放行。检查所有预期时钟与内部路径，无新增未说明的未约束路径、严重 DRC 或组合环；新增锁存器核实用途，不用资源预算替代功能正确性。
- 未达到时序标准的候选不得替换最新版 bit；报告真实结果。
- 构建脚本只从本文件（`docs/AGENTS.md`）读取时序值：`TIMING_MIN_WNS_NS=0.000`、`TIMING_MIN_WHS_NS=0.000`、`TIMING_MAX_TNS_NS=0.000`、`TIMING_MAX_THS_NS=0.000`。

## 每轮与最终复验

- 每轮是一组围绕同一目标的修改。每轮只运行受影响的功能测试；不在每轮无差别重复完整回归或整机布线。
- 修改流水线、组合逻辑深度、关键路径或相关时序连接后，及时做对应综合／时序检查，尽早确认路径、延迟和新的瓶颈；复用仍有效的检查点与报告。局部检查不替代最后的完整布线验收。
- 全部代码修改结束后，执行最终完整功能回归及整机综合、布局布线。代理负责状态机、计数与数据一致性、事务边界等功能仿真，检查工程编译、目标器件容量、布线合法性、DRC、时序及源码／资产／bit 对应关系。存储、调色板、音视频等逻辑按实际改动检查必要的连接与数据一致性。
- 完整功能回归按本次实际功能范围组织，可使用 `temporary/sim/run_all.bat` 或对应功能入口；不因旧入口包含画面或音频专项，就强制重复用户负责的实机验收。记录实际执行的测试与交由用户上板的项目，不以历史组数作为固定门槛。
- **真实 RTL 画面预览不再作为必做项**，包括单人、双人、菜单、游玩和结算；不要求为了交付而额外生成逐场景截图或预览总览。
- **可以直接通过上板观察、操作或试听确认的体验项目由用户验证**：画面布局、P1／P2 NEXT 位置、字体／颜色／遮挡、像素对齐与显示相位、核心／储备／提示／HOLD 反馈、菜单导航与操作手感、实际难度与供能平衡、PC 实际收流显示、HDMI 画面和人工试听等。代理列明改动及观察要点，不替用户宣称已上板通过。
- 像素／字形／覆盖遍历、实际路由网表文字有效区、逐样本音频和 TMDS 端到端专项也不再一律强制；相关呈现与体验交由用户上板验证。只有修改对应底层链路或遇到必须定位的具体问题时，代理才按需做对应专项；不因此恢复整套离线预览流程。
- 代理完成其负责的自动功能检查、完整布线时序和发布一致性检查后，可交付 bit 与用户上板核对项，不要求等待用户完成实机验收。用户未验收项标为“待用户上板验证”，不视为代理交付失败，也不冒称已经通过。
- 验证绑定最终源码、资产和构建输入指纹。后续改动使相关自动验证失效，必须补验；不拿历史报告或旧 bit 当作本轮结果。自动检查不能替代用户的实际画面、操作和试听反馈。
- 纯文档／目录整理只检查文件完整性、链接和引用；涉及构建、发布脚本修改则测试相关脚本并做必要的最终整体复验。硬件源码、约束、资产及实际构建配置未变，且已有对应输入的通过记录时，复用现有构建与验证证据，不重复综合或生成 bit；策略、日志目录等流程调整以脚本测试和现有检查点复核为主。

## bit 与 bin 保存

- Vivado 正式工程及 IP 运行不配置生成前／后的脚本钩子。界面 Generate Bitstream 只执行标准流程，原始输出为 `Tetris.runs/impl_1/Tetris.bit`，不自动运行 Python、读取维护文档或覆盖正式 `bit/Tetris.bit`；不得在构建脚本中恢复旧钩子。
- 本机 `tools/生成bit.bat` 是独立的完整构建／验证／保存入口，直接调用检查和发布函数；正式最新版仍须满足下列验证与归档规则。

- 本机各版本 bit、bin 统一放 `bit/`。最新版固定为 `bit/Tetris.bit` 和 `bit/Tetris.bin`，两者必须对应同一配置数据。
- 发布验证通过的 bit 时同步生成配套 bin，使用 `tools/publish_bitstream.py`；Tcl 发布入口调用同一实现，不能只更新其中一个。bin 严格解析 bit 文件头，保留原配置数据字节和位序；禁止直接改扩展名或修改配置包。转换格式需与 Vivado 原生输出对照验证。
- 替换前，各文件旧内容有变化才分别归档为 `bit/Tetris_YYYYMMDD_HHMMSS_SHA256前12位.bit`／`.bin`，各用自身哈希；相同内容不重复归档，已有具名旧版保留。先完成转换和暂存，替换失败恢复原发布文件；同一 bit 缺少 bin 时可补生成，不重复综合。
- 最新版只接受与最终源码匹配且整体复验通过的构建。候选 bit/bin 留在 `temporary/`，不得覆盖已验证最新版。只补转换／归档工具或文档且硬件输入未变时，复用原硬件验收并验证转换、归档、回滚与发布一致性，不能改写历史验收记录。
- Git、GitHub 当前树与作品包只保留最新一对 `bit/Tetris.bit`、`bit/Tetris.bin`。历史 bit/bin 仅本机保留并由 `.gitignore` 排除，不删除历史提交；两种扩展名在 `.gitattributes` 中均标为 binary，禁止换行或编码转换。
- `tools/生成bin.bat` 只从现有正式 `bit/Tetris.bit` 补生成配套 bin；完整构建入口在硬件验证通过后同步发布二者。不得为此给 Vivado 工程新增生成钩子；Flash 实际型号、启动模式及断电启动由用户上板确认。
