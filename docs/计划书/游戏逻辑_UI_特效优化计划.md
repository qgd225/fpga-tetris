## 4. 体验诊断

### 4.1 机制层

| 问题 | 证据 | 玩家感受 |
| --- | --- | --- |
| 左右长按基本只移动一次 | 当前没有 DAS/ARR 状态机 | 横向移动需要连点，操作不跟手 |
| 按键消抖注释与实测不一致 | `1_000_000` 周期约 13.47 ms，注释写 20 ms | 调参依据不可靠，输入延迟边界不清晰 |
| 锁定等待约 269 ms | `MCNT_LAND = 20_000_000` | 有缓冲，但缺少明确的可移动窗口定义 |
| 消行阶段约 85 ms | `CLEAR_STEP = 6_311_250` | 变化偏突然，缺少接触、确认、塌缩的层次 |
| 分数只来自消行 | `scoring.v` 仅在 `clear_t_t` 时加分 | 主动软降、硬降和连击没有正反馈 |
| 游戏结束只有布尔 `over` | 无法区分出生点占用、触顶、锁定失败 | 失败突然，玩家难以学习 |

### 4.2 动态层

- 高水平玩家会被横向连点限制，难以形成稳定节奏。
- 新手能看见危险颜色，但不一定知道是出生点受阻还是堆叠已触顶。
- 消行虽有动画，但反馈与计分、连击、下一块就绪之间缺少清晰的因果顺序。
- 双人模式共享同一堆叠、消行、比分与等级，仅活动块、NEXT/HOLD 和输入路径独立。

### 4.3 美学层

- 目标不是堆更多颜色，而是建立“响应、公平、清晰、短促庆祝”的体验。
- 大反馈只给消行、升级和游戏结束；移动、锁定、硬降只做小反馈。
- 危险和双人身份必须同时使用文字、位置和形状编码。

## 5. 体验目标

### 5.1 核心指标

| 指标 | 目标 | 上限 |
| --- | ---: | ---: |
| 按键下降沿到首次可见移动 | 小于 50 ms | 小于 100 ms |
| 硬降输入到落地反馈 | 1 至 2 帧 | 2 帧 |
| 锁定后到显示稳定堆叠 | 小于 80 ms | 120 ms |
| 完整消行管道 | 240 ms | 300 ms |
| 升级 HUD 脉冲 | 100 ms | 120 ms |
| 危险提示出现 | 下一个扫描周期 | 小于 50 ms |
| 反馈期间输入丢失 | 0 | 0 |

### 5.2 玩法目标

- 首次玩家在 30 秒内能完成“移动、旋转、硬降、消行”的完整循环。
- 熟练玩家可以使用长按连续横移，节奏不再依赖连点。
- 失败后 2 秒内能看懂是哪一侧、因为什么失败、怎样重新开始。
- 双人模式保持输入隔离，同帧事件不互相抢占。

### 5.3 资源与稳定性目标

- 全部优化完成后 LUT 目标不高于 92%。
- WNS 不低于 +0.150 ns。
- WHS 不低于 +0.050 ns。
- 所有新增反馈合计不超过约 200 LUT。
- 单个特效原则上不超过 80 LUT。

## 6. 逻辑优化

### 6.1 P0：输入响应与缓冲

**目标**

- 加入明确的 DAS/ARR 横向连发。
- 把消抖周期改为命名清晰的参数。
- 保证消行动画、升级反馈和下一块生成期间不丢输入。

**实施**

1. 在 `Key.v` 与 `Playfield` 输入路径之间增加横向重复状态机。
2. 首次按下立即移动一格，按下沿无额外延迟。
3. DAS 设为 132 ms，约 `9_801_000` 个 74.25 MHz 周期。
4. ARR 设为 33 ms，约 `2_450_250` 个周期。
5. 松开按键、切换左右方向、暂停、游戏结束和重新开始时复位 DAS/ARR。
6. 旋转、HOLD 和硬降只响应单次按下，不参与横向连发。
7. 消行阶段缓存最近 2 至 3 帧的旋转、移动和硬降事件，下一块就绪后按顺序消费。
8. 将 `key_filter` 的计数改为 `DEBOUNCE_CNT`，建议统一为 10 ms，即 `742_500` 个周期，并在注释中写明时钟频率和实测值。

**验收**

- 首次移动延迟小于 50 ms。
- 按住 131 ms 时不重复，达到 132 ms 后开始按 33 ms 重复。
- 方向切换后立即按新方向移动，不继承旧方向计时。
- P1 和 P2 的按住状态、DAS、ARR 完全独立。
- 消行期间输入不丢，下一块就绪后不连续误触发。

### 6.2 P0：游戏结束原因

**目标**

把单一 `over` 扩展为可显示的结束原因，不改变主要状态机结构。

**建议信号**

| 信号 | 作用 |
| --- | --- |
| `over` | 保持现有状态机兼容 |
| `over_side` | 触发触顶的活动块来源，0 表示 P1，1 表示 P2，单人固定为 P1 |
| `over_reason[1:0]` | 0 正常、1 出生点占用、2 堆叠触顶、3 锁定失败或非法生成 |

**实施**

1. 在 `Playfield.v` 结束时锁存原因和结束侧。
2. `Game_state_machine` 只消费稳定后的结束事件，避免组合逻辑抖动。
3. 结束画面显示触发来源、死因、共享最终比分和重开操作。
4. 双人模式说明这是共享场地的整局结束，避免误写成某一方独立失败。
5. 重新开始时在 `Finalize` 状态统一清除原因、连击和反馈计时器。

**验收**

- 三种主要死因能分别触发并锁存。
- 结束侧不会因双人同帧触顶而随机变化。
- 结束画面文字与代码记录一致。
- 重开后第一块从干净状态生成，不残留上一局反馈。

### 6.3 P1：计分与连击

**目标**

让主动操作产生可感知回报，同时控制 LUT 增量。

**建议规则**

| 事件 | 建议分值 |
| --- | ---: |
| 软降一格 | +1 |
| 硬降一格 | +2 |
| 消行 | 保留现有等级系数 |
| 连击 | 从第 2 次连续消行起，每次额外加基础分 |

**实施**

1. 计分输入增加软降和硬降的有效位移脉冲，不按按键次数计分。
2. 分数保持 20 位，并增加饱和处理，避免 BCD 显示回绕。
3. 双方共用同一比分和连击；任一活动块的有效操作都可以推进共享计分。
4. 连击计数器使用 3 位，非消行锁定时清零。
5. 连击放在共享统计栏，只在大于 1 时高亮。
6. 所有加分在单个提交脉冲发生，避免双方同帧锁定导致同一个消行重复累计。

**验收**

- 软降、硬降和消行分别有独立断言。
- 分数达到最大值后保持饱和，不回绕。
- P1/P2 的软降和硬降都累加到同一共享比分。
- 连击在非消行锁定后清零。
- 一局重开后计分和连击同时清零。

### 6.4 P1：锁定与危险状态

**目标**

保留当前约 269 ms 锁定缓冲的容错感，同时让危险状态更可解释。

**实施**

1. 将锁定周期改为具名参数，记录实际毫秒数。
2. 锁定窗口内允许有限次移动重置；建议最多 8 次，避免无限拖锁。
3. 危险区属于整块共享场地；第 0 至 1 行为红色，第 2 至 3 行为橙色。
4. 出生点被占用时优先报告“出生点占用”，不再只显示统一的顶部触顶。
5. 不改变当前等级阈值和下落速度曲线，先完成输入与解释性优化。

**验收**

- 锁定等待实际值与注释一致。
- 有界移动重置不会造成无限锁定。
- 危险标签、双方边线和行带同步出现。

### 6.5 P2：双人公平性

**目标**

保持活动块和输入隔离，同时明确堆叠、消行与计分是共享状态。

**实施**

1. P1/P2 的硬降和锁定事件分别提交，但都写入同一块 24×20 堆叠状态。
2. 同帧双方完成同一组满行时，共享行掩码只产生一次消行、一次计分。
3. 任一活动块触顶都结束整局共享对局，结束画面只标明触发来源。
4. 共享消行动画期间，P1/P2 输入都进入同一套缓冲队列。
5. 不新增网络同步逻辑，网络路径本轮只做回归验证。

**验收**

- P1/P2 同帧操作顺序确定，双方锁定都正确写入共享堆叠。
- 同帧满行只结算一次共享消行和共享比分。
- 任一活动块触顶后整局结束，当前锁定提交不被截断。
- `duo`、`frame_duo`、`input_route` 全部回归通过。

## 7. UI 优化

### 7.1 布局与安全区

**目标**

让玩家在 2 米观看距离和竞速状态下仍能快速读取。

**实施**

1. 所有文字 HUD 保持在画面 90% 标题安全区内，默认左右至少 5% 边距。
2. 中央保持一块连续 24×20 场地，不使用双场地分隔线或中间黑缝。
3. 共享统计栏显示比分、消行、连击和时间。
4. 等级使用左侧独立竖向条，八段填充作为主视觉，两位等级数字作为辅助信息。
5. P1/P2 侧栏使用镜像锚点，只显示各自独立的 NEXT/HOLD。
6. 场地仍可延伸到动作安全区，但关键 HUD 不贴屏幕边缘。
7. NEXT/HOLD 和等级条使用固定尺寸，不因内容变化移动布局。
8. P1/P2 标识固定在各自 NEXT/HOLD 上方，使用对应侧强调色和文字双重编码。
9. 右侧排行榜使用独立背景和分隔线，不与场地边框连续。
10. 正式 HUD 移除 DAS、ARR、GHOST、包统计和帧率等开发或设置信息。

### 7.2 HUD 信息

**常驻**

- 玩家标识 P1/P2，用于区分左右出生区和侧栏归属。
- 共享七位比分。
- 共享消行数。
- P1/P2 各自独立的 NEXT。
- P1/P2 各自独立的 HOLD。
- 左侧共享等级条，包含八段竖向填充、两位等级数字和满级状态。

**条件显示**

- 共享连击大于 1 时显示 `COMBO xN`。
- 共享堆叠进入危险区时显示整场 `DANGER`。
- 升级时只对左侧等级条做 100 至 120 ms 的局部扫描，不移动 HUD。

**不放入正式 HUD**

- DAS/ARR 数值。
- GHOST 开关。
- 大段操作说明。
- 调试计数器。

### 7.3 危险提示

- 红色用于第 0 至 1 行，橙色用于第 2 至 3 行。
- 同时使用 `DANGER` 文字、顶部警示线、双方边线和场内行带。
- 警示标签锚定在共享场地顶部，不虚构左右独立危险区。
- 危险呼吸动画上限 1.2 s，只改变亮度和边线，不抖动 HUD。
- 开启减少动态反馈时，呼吸改为静态高亮。

### 7.4 游戏结束与结果页

- 标题显示 `GAME OVER`。
- 第一行显示触发来源，例如 `P1 PIECE TOP OUT`，并说明共享对局结束。
- 第二行显示原因，例如 `SPAWN BLOCKED`。
- 显示最终比分和最高等级。
- 重开操作单独占一行，避免与死因混排。
- 结果页不遮挡仍需要展示的堆叠顶部与失败位置。

### 7.5 菜单与设置

设置页只保留对当前硬件最有价值的选项：

| 选项 | 取值 | 默认值 |
| --- | --- | --- |
| `FX` | FULL / REDUCED / OFF | FULL |
| `GHOST` | ON / OFF | ON |
| `SAFE AREA` | 90% / 95% / 100% | 95% |
| `RESTART` | HOLD / SHORT | HOLD |

菜单焦点必须同时使用边框、尺寸或角标表达，不能只改变颜色。

### 7.6 字模与可读性

- 继续使用现有 5x7 像素字模，避免新增大型字库。
- 正文在 1280x720 输出中不小于约 14 px 高。
- 关键数字使用玩家侧强调色，并保留白色标签。
- 数字与标签底色对比不足时增加 1 至 2 像素黑色阴影。
- 所有英文标签保持短词，禁止把长说明塞入场地边缘。

## 8. 特效优化

### 8.1 分级原则

一个事件只选 2 至 3 个通道，反馈必须在 300 ms 内回到静止状态。

| 等级 | 事件 | 反馈组合 |
| --- | --- | --- |
| 小 | 移动、软降、旋转 | 边缘亮 1 至 2 帧，无闪烁、无抖动 |
| 中 | 硬降、锁定、HOLD | 短拖影、局部边缘、对应音效 |
| 大 | 消行、升级、游戏结束 | 行闪白、扫描、塌缩、局部脉冲、HUD 扫描 |

### 8.2 事件与通道

| 事件 | 视觉反馈 | 上限 |
| --- | --- | ---: |
| 横向移动 | 方块靠近边缘处亮 1 帧 | 1 帧 |
| 软降 | 方块底边短亮 | 1 帧 |
| 硬降 | 2 帧纵向拖影、落地白线 | 33 ms |
| 锁定 | 左右边线局部脉冲 | 80 ms |
| 消行 | 接触、闪白、扫描、塌缩、下落、稳定 | 300 ms |
| 升级 | 左侧等级条扫描 | 120 ms |
| 危险 | 1.2 s 呼吸边线 | 1.2 s |
| 游戏结束 | 场地压暗、结果文字进入 | 180 ms |

### 8.3 消行管道

| 阶段 | 时间 | 状态 |
| --- | ---: | --- |
| 接触 | T+0 ms | 锁存完整行和颜色 |
| 闪白 | T+16 ms | 完整行高亮 1 帧 |
| 扫描 | T+48 ms | 从左向右确认 |
| 塌缩 | T+96 ms | 行边缘向内收 |
| 下落 | T+144 ms | 上方堆叠下移 |
| 稳定 | T+192 ms | 新堆叠边线局部脉冲 |
| 计分 | T+240 ms | 分数、连击、等级提交 |
| 就绪 | T+300 ms | 下一块可操作 |

### 8.4 资源控制

- 复用现有 `clear_flash`、`line_t`、`clear_row`、`danger_lvl` 和边线逻辑。
- 不新增每格粒子数组。
- 不做全屏随机抖动。
- 不新增第二套全场扫描状态机。
- 拖影只保存最近 1 至 2 帧位置，不保存完整历史。
- 所有计时器由事件脉冲启动，不允许永久递增。

### 8.5 建议 LUT 预算

| 项目 | 建议上限 |
| --- | ---: |
| 移动/软降边缘脉冲 | 20 LUT |
| 硬降两帧拖影 | 40 LUT |
| 锁定局部边线 | 30 LUT |
| 消行阶段扩展 | 50 LUT |
| 计分/连击提示 | 35 LUT |
| 危险呼吸 | 25 LUT |
| 结束原因与结果页 | 60 LUT |

这些条目不会同时达到上限，全部新增反馈合计控制在 200 LUT 左右。

### 8.6 无障碍

- `FX=FULL`：全部短反馈可用。
- `FX=REDUCED`：关闭呼吸和闪烁，保留静态边线、文字和计分提示。
- `FX=OFF`：关闭所有非必要视觉反馈，保留状态变化和结果信息。
- HUD 永远不参与场地闪烁、抖动或缩放。
- 颜色信息始终有文字或形状备份。

## 9. 资源腾挪计划

### 9.1 前置目标

在新增玩法前，先从组合逻辑热点恢复 500 至 800 LUT，并保持现有行为不变。没有这笔预算，不进入特效实现。

### 9.2 候选清理

1. 将 20 行满行判断集中为一次性行掩码，供清行、计分和渲染共享。
2. 检查 `Playfield` 内重复的边界比较、行比较和颜色选择，优先合并等价条件。
3. 检查 `solo_hint` 与主场地是否重复扫描同一组行状态，可共享只读结果。
4. 保持 `hdmi`、网络协议和 PLL 不变，避免把风险引入显示链路。
5. 对每个小改动单独综合，记录 LUT、WNS、WHS 和 8 套仿真结果。

### 9.3 停止条件

- LUT 超过 94%：立即回退当前改动。
- WNS 低于 +0.100 ns：当前改动不得合入。
- 任一现有仿真失败：先修复逻辑，再继续优化。
- 单个特效超过 80 LUT：重新设计或取消。
- 全部新增反馈超过 200 LUT：停止新增，只保留最高价值反馈。

## 13. 风险与回退

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| Playfield 组合逻辑继续膨胀 | 无法布线或时序余量消失 | 先做行掩码共享和重复条件合并 |
| DAS/ARR 与现有按键脉冲冲突 | 一次按键重复移动 | 只在真实按住且方向不变时计时 |
| 消行反馈阻塞下一块 | 操作节奏变慢 | 300 ms 硬上限，输入始终缓冲 |
| 双人同帧写入共享堆叠 | 锁定覆盖或同一满行重复计分 | 集中生成一次共享行掩码和单次消行提交脉冲 |
| 新字模或结果页占用 BRAM | 显示链路拥塞 | 复用现有字模和局部文字块 |
| 闪烁过强 | 视觉疲劳或不适 | FULL/REDUCED/OFF 三级反馈 |
| 资源超限后才回退 | 冻结日前返工 | 每项独立综合，达到停止条件立即回退 |

### 回退顺序

1. 关闭本轮新增视觉特效，保留逻辑和 UI。
2. 将消行动画恢复为现有短管道。
3. 保留结束原因和 HUD 安全区修正。
4. 若资源仍超限，回退到功能冻结前的已通过版本。
5. 任何回退都必须重新运行全 8 套仿真和实现时序检查。
