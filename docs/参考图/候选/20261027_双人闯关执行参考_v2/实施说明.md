## 唯一外观依据

`00_主参考_原图不改.png` 为本次用户附图的原文件副本，逐字节一致。七张 `modules/*.png` 是其原尺寸矩形裁切，逐像素一致，没有生成、补画、重新着色或更换字体。`01_冻结模块标注.png` 仅为标注副本，彩色框不属于游戏画面。

v1 的工程重建图不再作为外观目标，不允许按它简化材质、改变面板轮廓或重画文字。先前按两个不同来源组合的选项，现在以本次用户附图中的最终组合为准。

## 七个冻结部件

| 部件 | 必须保持 |
| --- | --- |
| 管道 | 细橙管、短横套口、45度折角、一次轻微错位、青色窗口、固定卡箍、核心侧接头；不改成粗管、大蛇形或另一套管路。 |
| 核心 | 原外壳长宽关系、顶盖锁扣、支架、边条、段舱切角和像素高光；不重画成简单矩形柱。 |
| 刻度 | 原圆点、细竖线、当前箭头与字形；自下往上 RECONNECT、REBUILD、STABILIZE、RECHARGE。 |
| 船况头 | 原飞船剪影和三斜杠、SHIP字形、双轨标签和百分比区域、内凹边与金属表面。 |
| P1 NEXT | 原面板切角、加宽区、青色P1的形状和相对位置、NEXT字形和槽口压边。 |
| P2 NEXT | 与原图完全同款，品红P2；不能把P1/P2做成独立八角耳朵、细长旗帜或挤偏标题。 |
| HOLD | 原暗面板、居中文字、空槽凹边及三小格；不新增P1，不恢复下挂装饰板。 |

## 实现约束

1. 优先保留原素材：移动模块、统一等比缩放、拆分动态覆盖区均可；不能整模块非等比拉伸，不能重画外形、随意换字形或以近似配色替换全部纹理。若拉长直管或轨道，使用原直段平铺及端帽固定，不能连字形、弯头一同拉长。
2. 图片里的数字、方块预览和灯态为样例。接入RTL时要制作独立静态底板和动态掩码，不能将样例文字或方块固化进实时游戏。静态底板清理后的局部需对照原图复核，避免保留旧字残影或双重边框。
3. 原图视觉细节是外观标准，实际业务仍按 `docs/游戏模式_玩法规格.md`：八段核心，LOCKED=0、HALF≤4、ONLINE未成功≤7、成功才为8。原图中的琥珀底舱是壳体警示件，不能算青色充能段。不能为了复制示意图改变核心算法。
4. 双人仅一个共享HOLD、两个NEXT，无HINT。两名玩家普通落点幽灵不等于智能落点。HOLD无常驻玩家标签，预约/拒绝等反馈仍需表达实际请求玩家和状态。
5. 原图本身的中央场地不是严格24×20几何；真实运行场地仍为576×480、24×20、单格24。实施时允许只调整中央动态区和周边留白，移动冻结模块以避让。不得以“纠正比例”为理由再次重绘七个冻结部件。图中源坐标仅用于裁切和比对，不冒充已经解决所有布局约束的RTL坐标。
6. 真正需要更改冻结模块的外形或内部排版时，先给原图与改后局部的对照，由用户定夺；不能自行改完再称为“几乎一样”。
