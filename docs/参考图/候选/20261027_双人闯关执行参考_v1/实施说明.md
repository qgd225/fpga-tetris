## 必须保留的造型

- 船况头采用认可原图的 SHIP 字样、小飞船、三条斜杠、双轨金属凹槽、青色 CHARGE 和琥珀斜纹 DEBRIS。示例百分比为辅助图案，实际任务保留真实分子/分母，不因原图示意百分比改变算法。
- NEXT 左上是整块暗面板适度加宽，不是独立八角耳朵。P1 青、P2 品红；色块与 NEXT 标题有各自空间，标题以预览槽中心为准。
- HOLD 共用一个槽，三格不扩大成按钮。没有常驻 P1/P2 标签；原先的预约/拒绝/过期反馈仍须可辨认。具体预约边框按请求玩家着色并用小箭头表意，不能因为隐藏常驻标签而取消功能反馈。
- 管路只做一次轻微错位避让，保持细管、45 度折角、小套口和少量青色输送窗，不画大蛇形多重弯折。上端与 CHARGE 轨道同轴；下端必须实际接到核心侧套口。
- 整圈船壳连续。螺栓、通风槽、凹线属于船壳表面，不能按开发模块单独圈成装饰面板。外围不再增加伸出画外的粗管束、机械臂。

管道中心点列为 `(928,68) → (1084,68) → (1104,88) → (1104,138) → (1116,150) → (1116,414) → (1120,418)`。外壳宽12、橙色内管宽6。转角套口不得侵入 P2 NEXT，入口与 CHARGE 同一水平线。输送光是临时反馈，不是额外能量计数。

## 状态与数据绑定

继续使用 `docs/游戏模式_玩法规格.md` 的现行规则；只调整表达，不重算分数、记功或残骸。

| 显示 | 数据与规则 |
| --- | --- |
| CHARGE | 闯关累计记功/本船目标；每批 `n+(n==4?2:0)`，一至四行跳字为 +1/+2/+3/+6。超过目标而残骸未清完，保留真实分子。 |
| DEBRIS | 当前剩余残骸格数；轨道按剩余/本关初始残骸总量缩短；不和实际消行累计混用。 |
| 核心段数 | `floor(8×记功/目标)` 后施加三态上限；LOCKED=0，HALF≤4，ONLINE 未成功≤7，成功才为8。 |
| 阶段 | 可见段数0～2 RECONNECT；3～4 REBUILD；5～6 STABILIZE；7～8 RECHARGE。允许跳阶，不等待动画补齐才更新业务。 |
| HOLD 三格 | 依次是本块允许存入、块数冷却完成、2秒冷却完成；不表示残骸任务或玩家独占。 |
| TIME | 现有有效游戏时间，暂停冻结；与核心或动画无独立计时器。 |

四阶从底到顶的文字位置：RECONNECT y=582、REBUILD y=518、STABILIZE y=454、RECHARGE y=390。过去阶实心点，当前阶箭头和亮字，未来阶空心点。图中HALF=3段，所以REBUILD是倒数第二阶。

样例锁定为 DUO CAMPAIGN / SHIP 02：目标35，剩余18，HALF阈值20，记功15，可见3段，阶段REBUILD，TIME 02:18。场地样例中恰好18个残骸格。样例用于比对显示，不替换实际关卡模板。

双人没有智能落点，没有HINT额度和推荐中心靶框；双方普通落点幽灵继续保留。单人智能落点另做专属参考，不占双人P2 NEXT。

## 图层、材质与实现入口

图层从后到前为静态船壳/管路、场地底纹、预览槽、活动与落定块及幽灵、核心/刻度、短反馈。总坐标唯一，任何分层素材不得自行再缩放。各PNG尺寸为1280×720，直接按屏幕坐标取样。

`layers/01_static_shell.png` 为视觉参考合成底图，含示意文字，不得直接作为包含实时数值的整屏背景ROM；实际接入需将SHIP、CHARGE、DEBRIS、NEXT、HOLD、SPD、TIME等实时内容从静态材质中剥离，继续使用运行时信号。其余层也均是本包的静态样例，不会自行响应输入。

正式接入建议入口：`story_layout.vh` 维护坐标；`story_ui.v` 组织图层、文本和数据；`core_renderer.v` 负责核心三态；`story_scene.v` 负责背景和管道；`story_palette.vh` 维护颜色。按模块边界接入，是否拆新模块以实际代码耦合判断，不为装饰框强行拆屏幕。

七种方块基色沿用现有调色板：I `#38B6C8`、T `#9B6BB5`、O `#D9B23C`、Z `#C2453A`、S `#4FA86B`、L `#D97B33`、J `#3E6FBF`。灰蓝残骸 `#526774` 加细短斜裂纹。高光/阴影由参考材质对应现有色阶；不能用播放器身份色覆盖方块类型色。普通幽灵使用类型色空心虚线、无推荐中心点。块面22×22，格距24。

源图的材质不等于必须引入全屏RGB帧缓存。RTL按既有逐像素调色板架构制作静态材质、掩码或分区ROM，动态内容仍接入现有逻辑。保存当前管线的文本/材质/RGB时延对齐；任何时延调整需要同步检查所有命中与色号信号。

## 实施顺序与验收

1. 先固定布局与命中区域，验证场地576×480、槽112×112、无HINT、完整P2 NEXT。
2. 接静态船况头、NEXT/HOLD面板与连续壳体材质，不改玩法。
3. 接CHARGE/DEBRIS、核心三态和四阶状态，保留已完成任务划线。
4. 接预约/拒绝/过期反馈、记功跳字、清骸火花、管道输送和状态扫光；暂停冻结，终局/重开取消旧反馈。
5. 按受影响范围功能验证，结束后遵循工程的最终回归、整机布线与发布一致性要求。当前包本身仅做文件和几何检查，不宣称硬件验证通过。

自动检查：矩形边界、场地24×20、槽等大正方形、核心8段和节距、阶段顺序、样例15/35对应3段、18格残骸、普通幽灵不与堆积重叠。视觉材质、字形、实机清晰度与操作反馈仍需实际制作后上板核对。
